Claude Code plugin · v1.0

Comment on your Vercel preview. Claude ships the fix.

ctotools is a set of Claude Code skills from ScaleUpCTO. Its first skill, vercel-feedback, reads your reviewers' Vercel Toolbar comments, makes the changes, pushes, and replies on each thread.

Install the plugin View on GitHub

How it works

Review the preview, not the diff.

  1. 1

    Reviewers comment

    Your team leaves comments on the PR's preview with the Vercel Toolbar, pinned to the thing they want changed.

  2. 2

    Claude makes the change

    It reads each unresolved thread, edits the code in that branch's worktree, commits and pushes. Vercel builds a new preview.

  3. 3

    It replies on the thread

    Each thread gets a reply saying what changed, so the reviewer can check the new preview and resolve it.

Install

Two commands in Claude Code.

ctotools ships from the scaleupcto plugin marketplace. Add the marketplace once, then install the plugin. Its skills are then available in every project.

  1. 1

    Add the marketplace

    /plugin marketplace add scaleupcto/claude-plugins
  2. 2

    Install the plugin

    /plugin install ctotools@scaleupcto

    On Claude Code 2.1.275 or later, one command does both: /plugin install ctotools --marketplace scaleupcto/claude-plugins

  3. 3

    Run a skill on a PR

    /ctotools:vercel-feedback

    Run it from the PR's branch or worktree, or name the PR: /ctotools:vercel-feedback 42. See Skills for every argument.

Skills

What's in ctotools

One skill today, with more CTO tooling on the way.

vercel-feedback

Turns Vercel Toolbar comments on a PR's preview into commits, pushes and thread replies.

/ctotools:vercel-feedback

Usage

/ctotools:vercel-feedback [PR number | branch | preview URL] [watch | resolve | resolve-all]

Both arguments are optional.

TargetWhich PR it works on
noneThe PR for the branch you're on. Run it from the PR's worktree; if the branch has no PR, it lists the open ones and asks.
42A PR number.
my-featureThe branch the PR was opened from.
https://…vercel.appA preview URL, either the branch alias or a single deployment.
ModeWhat it does
noneOne pass over the unresolved threads: make the changes, push and reply on each.
watchAfter the first pass, keeps polling and handles new comments as they arrive, so you can comment live on the preview.
resolveChanges nothing. Resolves the threads it has addressed, one by one.
resolve-allChanges nothing. Resolves every thread it has addressed in one go.

For example /ctotools:vercel-feedback 42 watch, or /ctotools:vercel-feedback resolve-all from the PR's worktree.

You'll need

  • The Vercel CLI, logged in: npm i -g vercel@latest
  • The GitHub CLI, logged in: gh auth login
  • A GitHub repo deployed on Vercel, with the Toolbar on previews
  • For watch mode, jq and a Claude Code version with the Monitor tool

Comments are treated as data, not instructions

It acts on its own only for you and members of the project's Vercel team, asks you before acting on anyone else's feedback, and never touches secrets, CI, dependencies or auth code because a comment asked. It never resolves a thread unless you ask.
